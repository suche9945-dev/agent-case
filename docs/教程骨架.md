# 教程骨架（五篇通用）

这一篇以 `content/guides/deepseek-harness-guide.md` 为样板：小节标题、每节的写法、截图清单都按它来，其余四篇照着填。

## 一、frontmatter

```yaml
---
title: 10–40 字，写清「谁看完能干什么」，不要写成「XX 工具介绍」
tool: 必须是 data/products/ 里的文件名
summary: 40–80 字，一句话说清谁、能学到什么
updatedAt: YYYY-MM-DD，内容核对日期
screenshots: []            # 图先不放，拍完再补
sourceUrls:                # ≥3 条，正文每个事实的落点
  - https://官方文档地址
---
```

## 二、开头那段「这篇覆盖什么」

正文第一个 `##` 之前，用一段引用块写清三件事：

> **这篇覆盖什么**：装好 → 接模型 → 跑通第一个任务 → 接自己的 Key → 付费与排错。
>
> **你需要准备**：账号、一个文件夹、约多少分钟。

读者先知道要花多久、要不要往下看，比上来就讲功能有用。

## 三、九个小节（顺序固定）

| 小节 | 必须写到什么 | 判断标准 |
|---|---|---|
| `## 它能做什么` | 2–3 句讲清适用场景，**也讲清不适用场景** | 读者能判断「这工具是不是给我用的」 |
| `## 国内怎么用` | 官方支持地区、账号类型、实名、手机号、支付 | 和 `accessCN` 不矛盾 |
| `## 安装` | 各形态分开写，命令逐字抄官方，标核对版本 | 照着敲能装上 |
| `## 登录与开通` | 怎么登录、要不要先订阅、免费档能用到什么程度 | 能走到「可以开始用」 |
| `## 跑通第一个任务` | 3–5 步，每步写「点哪里 / 输入什么 / 看到什么」 | 没有「按提示操作即可」 |
| `## 接入自己的模型 / API Key` | 能填什么、兼容哪些协议、以官方为准 | 说清字段和坑 |
| `## 怎么付费` | 不写死价格，指向官方价格页或站内套餐页 | 价格变动时不用改文 |
| `## 常见问题` | 3–5 条，每条「现象 → 原因 → 怎么办」 | 能对上读者屏幕上的报错 |
| `## 延伸阅读` | 官方 2–4 条；第三方只放你实际读过的 | 链接都能打开 |

## 四、小节内部的结构

能用 `###` 拆就拆，右栏目录会自动出二级：

- 安装：`### 桌面版` / `### 命令行版` / `### 从源码跑（可跳过）`
- 登录：`### 第一步：拿 Key` / `### 第二步：填进工具`
- 跑通任务：`### 1. 选工作区` / `### 2. 先让它读` / `### 3. 再让它写` / `### 4. 验收`

每节尽量落在同一个节奏上：**目标 → 步骤 → 验收（看到什么算过）**。

## 五、写法约束

- 第二人称，书面但友好。
- 命令、参数、菜单名照官方原文，不翻译成中文。
- 坑写成「现象 → 原因 → 怎么办」，三句齐。
- 不许出现：强大的、一站式、赋能、轻松上手、无论你是……还是……、在当今 AI 时代。
- 每个事实都要能在 `sourceUrls` 里找到依据；官方和第三方冲突时以官方为准。

## 六、配图

- 每篇 ≥6 张，≥2 张自己实机截。
- 命名 `01-下载页.png` 这种，放 `public/guides/<slug>/`。
- 每张图注写来源：本人实机截图 / 官方页面 URL / 第三方教程链接。
- 不许 AI 生成假界面；图里不能有账号名、邮箱、Key、真实姓名、本机用户名。
- 具体到每一张拍什么，见 `docs/截图清单-deepseek-harness.md`。

## 七、交付前自检

1. `pnpm import:guides` 通过，`data/guides.json` 里有这一条。
2. 页面打开，右目录能跳、能高亮。
3. 汉字数 1500–3000（不含代码块和表格）。
4. 抽查两条安装命令，和官方文档逐字一致。
5. 图都标了来源，隐私信息已打码。
