# 评分表

总分 100，按四个维度打分。评分依据是**能复现的证据**（命令输出、截图、git 记录），不是「感觉做得不错」。

| 维度 | 权重 | 看什么 |
|---|---|---|
| A. 页面实现 | 30 | 三栏结构、目录状态、TOC 滚动高亮、响应式、可访问性、代码结构 |
| B. 导入链路 | 15 | 校验是否真的拦住错、报错信息是否可读、幂等、页面是否真的只读生成物 |
| C. 教程内容 | 40 | 是否实机跑通、步骤能不能照做、事实有没有出处、写法是否去 AI 味、截图质量 |
| D. 工程与交付 | 15 | TS strict、样式规范、提交过程、交付说明 |

## A. 页面实现（30）

| 分值 | 标准 |
|---|---|
| 26–30 | 三栏结构完整；22 个工具分组正确、5 个可点其余置灰；当前项高亮；TOC 滚动高亮准确；三个宽度都正常；键盘能走完；组件拆分合理，没有一坨 800 行的 page.tsx |
| 20–25 | 结构完整，个别交互（滚动高亮、折叠状态）有 bug 或只在桌面端正常 |
| 14–19 | 只有一个列表页或只有详情页；或三栏做成了两栏；或移动端直接横向溢出 |
| < 14 | 页面打不开，或明显是占位页改了个标题 |

## B. 导入链路（15）

| 分值 | 标准 |
|---|---|
| 13–15 | 四类错误全部拦住，一次列全；不写半成品；幂等；页面端没有硬编码 |
| 10–12 | 拦住了大部分错误，但有一类漏了（常见：截图文件存在性），或报错只报第一条 |
| 6–9 | 脚本能生成 json，但不校验或只校验了必填字段 |
| < 6 | 没有脚本，正文写死在组件里 |

## C. 教程内容（40）

| 分值 | 标准 |
|---|---|
| 34–40 | 5 篇都真的装过、跑通过；步骤精确到「点哪里」；坑写清了现象和原因；官方命令逐字一致；关键步骤有自己的实机图，借来的图都标了来源、没露个人信息；没有 AI 腔；读者照着能做完 |
| 27–33 | 4–5 篇达标，其余偏「官方文档复述」；个别事实没出处；图的数量够但来源标得不全 |
| 18–26 | 大部分是转述，没有实机痕迹；步骤停在「按提示操作」；图全是宣传图、没有一张自己的 |
| < 18 | 编造界面、用 AI 生成的假截图，或整篇搬运别人的教程 |

## D. 工程与交付（15）

| 分值 | 标准 |
|---|---|
| 13–15 | 无 `any`；无写死色值；分阶段提交；`DELIVERY.md` 写清了取舍和没做完的部分 |
| 10–12 | 基本规范，个别地方偷懒（内联样式、一个 commit 全包） |
| 6–9 | 有 `any`、写死一堆颜色，或把数据改坏了导致构建不过 |
| < 6 | 交上来跑不起来，或没有交付说明 |

## 硬性不通过

出现任意一条，直接不通过，不看分数：

1. 教程里的界面、截图是 AI 编造的，或整篇搬运别人的教程；
2. 页面跑不起来，或 `pnpm build` 不过；
3. 教程不足 5 篇，或没覆盖到 2 个分类；
4. 直接把 `content/guides/*.md` 的内容复制进组件，绕过导入链路。

## 加分项（不超总分 100，最多加 5 分）

- 皮肤切换器（夜墨 / 石墨白）真的能用，且颜色全部走 tokens；
- 目录里能直接搜到工具名（前端过滤即可）；
- 图片懒加载 + 合理占位，不跳版；
- 教程正文里能显示「这篇文章覆盖了哪些小节」的完成度提示。

## 档位

| 分数 | 结论 |
|---|---|
| 85–100 | 可以直接上手站点开发 |
| 70–84 | 合格，需要带一带 |
| 60–69 | 待定，看成长速度 |
| < 60 | 不通过 |
