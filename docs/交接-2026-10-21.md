## 1. 项目要做什么

给站内 22 个 AI 工具做一个「工具指南」模块：

1. `/guides` 总览页：左边 22 个工具分三组（编程 14 / 图像视频 5 / 办公 Agent 3），可折叠；有教程的 5 个能点，其余置灰写「教程整理中」；中间是说明与教程卡片；右边「本页目录」。
2. `/guides/<slug>` 教程页：分类标签、标题、摘要、更新时间、工具信息条（logo、官网、国内可用、免费档）、Markdown 正文、右目录滚动高亮、上一篇/下一篇、404。
3. 5 篇真实教程，覆盖至少 2 个分类，每篇 1500–3000 汉字、≥6 张图（其中 ≥2 张本人实机截图）。
4. 教程必须走链路：`content/guides/*.md` → `pnpm import:guides` → `data/guides.json` → `src/lib/` → 页面。
5. 交付说明 `DELIVERY.md`。

## 11. 小词典（给不熟悉术语的人）

| 词 | 意思 |
|---|---|
| 分支（branch） | 一条并行的代码线，`intern/chen` 是你的工作线，main 是主干 |
| 提交（commit） | 一次带说明的存档点，可以回退 |
| 暂存（git add） | 把改动放进「下一次提交」的篮子 |
| `git add -p` | 同一次改动里挑一部分行放进篮子，用来把五篇教程拆成五个提交 |
| PR | Pull Request，请求把分支合进 main，附带说明与评审 |
| frontmatter | md 文件开头 `---` 之间的元数据（标题、工具、日期等） |
| slug | 文章/工具的唯一短名，例如 `cursor-guide` |
| 构建（build） | 把源码编译成可部署产物，交付前必须通过 |
| 类型检查（typecheck） | 检查 TypeScript 类型错误，不生成文件 |
| 幂等 | 同样输入重复执行，结果完全一样 |
| 原子写入 | 先写临时文件再整体替换，失败不会留下半截文件 |
| AST | 把 Markdown 解析成的语法树，标题/目录都从它来，保证一致 |
| realpath | 路径的「真实位置」，能看穿快捷方式（junction/symlink） |
| 回归测试 | 改完之后重跑原有检查，确认没弄坏旧功能 |
