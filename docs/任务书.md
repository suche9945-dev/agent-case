# 任务书 · 工具指南页面

> 这份文件是完整要求。README 是入口，验收看 `docs/验收清单.md`，评分看 `docs/评分表.md`。

## 1. 背景

起源AI 是给国内 AI 新手和参赛者看的信息站：AI 工具与会员测评、限时福利、全国 AI 比赛。站内已经有 22 个工具的档案——它们能干什么、国内能不能用、有没有免费档。缺的是**下一步**：

> 我已经决定要用 Cursor 了，然后呢？在哪下载、怎么登录、第一个任务怎么跑、卡住了怎么办？

工具指南页就是回答这个问题的。它不是一个"工具列表"，而是一份**能照着做完的上手文档**。

## 2. 你要交付什么

> 动手之前先双击 `design-demo/index.html`，把整站的设计 demo 点一遍——首页、模型榜、工具筛选、比赛赛程、搜索、主题切换。工具页里 opencode、Claude Code、Codex、Cursor、TRAE、WorkBuddy 的套餐详情，就是你要做的教程页要衔接的东西。

| # | 交付物 | 具体要求 |
|---|---|---|
| 1 | 工具指南页面 | `/guides` 总览页 + `/guides/[slug]` 教程页，见第 3 节 |
| 2 | 导入脚本 | `pnpm import:guides` 把 `content/guides/*.md` 变成 `data/guides.json`，见第 4 节 |
| 3 | 5 篇教程 | 自己选 5 个工具，实机跑通，写成可照做的教程，见第 5 节 |
| 4 | 交付说明 | 根目录 `DELIVERY.md`：怎么跑、做了什么取舍、为什么选这 5 个、每篇的核对来源、没做完的部分 |

## 3. 页面

### 3.1 页面结构（对照 `docs/参考/` 里的参考截图）

**`/guides` 总览页**

- **左栏 · 工具目录**：22 个工具，按「编程工具 / 图像与视频 / 办公 Agent」三组展示，每组可折叠。
  - 有教程的 5 个可以点，点进去是教程页；
  - 没有教程的置灰，右侧标「教程整理中」，不可点。
  - 当前所在文章的目录项要有高亮。
- **中栏 · 正文**：一句话说清这个页面是干什么的、「怎么看这份指南」（3–4 条，讲清教程都覆盖了哪些内容）、然后 5 篇教程的入口卡片（标题、一句话摘要、工具名、更新时间、预计阅读时长）。
- **右栏 · 本页目录**：本页有几个小节（例如「怎么看这份指南」「全部工具」「新手先读这三篇」），点击能跳到对应位置。

**`/guides/[slug]` 教程页**

- 顶部：分类标签（编程工具 / 图像与视频 / 办公 Agent）、文章标题、摘要、更新时间。
- **工具信息条**：从 `data/products/<tool>.yaml` 取 logo、名字、tagline、官网链接、「国内可用 / 官方国内不可用」、免费档说明。这是教程和工具档案之间的连接，别漏。
- 正文：Markdown 渲染。
- 右栏：本页目录，从正文的 `##` / `###` 提取，滚动时高亮当前小节。
- 底部：上一篇 / 下一篇（顺序见 4.2），以及「返回全部工具」。
- `slug` 不存在时走 `notFound()`，不要返回空页面。
- 每篇文章要有自己的 `<title>`（`generateMetadata`）。

### 3.2 交互

- 左目录：当前文章高亮；分组可折叠（默认全部展开）。
- 右目录：点击平滑跳转；滚动时当前小节高亮。
- 移动端（≤ 768px）：左目录收起成顶部一个「全部工具」下拉/抽屉，右目录隐藏。
- 键盘：Tab 能走完所有可点元素，焦点样式可见；折叠按钮要有 `aria-expanded`。

### 3.3 视觉

- **结构**参照 priceai 的指南页（`docs/参考/`）；**长相**参照 `design-demo/`（双击 `index.html`，整站能点）。
- 站内内页是「石墨白」皮肤（浅色），`<html>` 已经带 `data-skin="paper"`，**不要改回深色**。首页那块深色星图是首页专用，不要搬到指南页。
- 颜色、字体、间距、圆角只用 `src/styles/tokens.css` 里的变量。全站方角、无阴影，靠 1px 的线分隔。
- 强调色（朱红）只用在印章、主按钮和「当前项」，别大面积铺。
- 三个宽度都要能用：1440 / 768 / 390。
- 组件样式写 `*.module.css`，不要写内联样式，不要在组件里写死色值。

### 3.4 技术约束

- Next.js 16 App Router + TypeScript `strict`。**不许出现 `any`**。
- 页面只读 `src/lib/` 里的函数，不要在组件里直接 `fs.readFileSync`。
- 不引入 Tailwind、UI 组件库、动画库、外部字体、外部图片、CDN 资源。
- 除了 `pnpm import:guides`，不改 `package.json`；要加依赖在 `DELIVERY.md` 里说明理由。
- `src/app/layout.tsx` 是站点外壳，尽量别重做（只加导航项就行）。数据、令牌、`products.ts` 想改可以改，改了什么在 `DELIVERY.md` 里说一句，保证 `pnpm build` 还能过。

## 4. 导入链路

### 4.1 教程的源文件

每篇教程是 `content/guides/<slug>.md`，frontmatter + Markdown 正文。完整格式和示例见 [`content/README.md`](../content/README.md)。

### 4.2 导入脚本

写 `scripts/import-guides.mjs`，`package.json` 里的入口已经留好了：

```bash
pnpm import:guides
```

必须做到：

1. 扫描 `content/guides/*.md`，`slug` 取文件名（去掉 `.md`）。
2. 用 `yaml` 解析 frontmatter，用 `zod` 校验字段，字段集合见 `content/README.md`。
3. **校验并拒绝**下面这些情况，一条都不许放过：
   - frontmatter 缺失、字段缺失、字段类型不对；
   - `tool` 在 `data/products/` 里不存在；
   - `updatedAt` 不是 `YYYY-MM-DD`；
   - `screenshots` 里的文件在 `public/` 下不存在；
   - 两个文件的 slug 相同（文件名大小写不同也算）。
4. 报错格式：`<文件>:<字段>: <原因>`，一次把所有文件的错误都列出来，然后**退出码 1**，且**不要写** `data/guides.json`（不能留半成品）。
5. 成功时写 `data/guides.json`：数组，按 `updatedAt` 倒序（同一天按 slug 升序），字段见 `src/lib/guides.ts` 的 `Guide` 类型。**上一篇 / 下一篇按这个数组的顺序**。
6. 幂等：内容不变时连跑两次，`data/guides.json` 逐字节一致（不要写时间戳之类的动态内容）。
7. 控制台输出一行汇总：读了几个文件、通过几个、写了几条。

### 4.3 页面怎么用

页面只读 `data/guides.json`（`src/lib/guides.ts` 已经写好了）。`content/guides/*.md` 是给作者看的源文件，不进页面构建。

## 5. 5 篇教程

### 5.1 选哪 5 个

- 从 22 个工具里**自己选 5 个**。
- **至少覆盖 2 个分类**（编程工具 / 图像与视频 / 办公 Agent）。同一类里挑 5 个编程工具不行。
- 在 `DELIVERY.md` 里写清选择理由：为什么是这 5 个，对国内新手来说它们的优先级在哪。
- 建议：优先选**官方有中文文档、你能真的拿到账号或能接国内模型**的。你装不上、跑不通的工具，别选。

### 5.2 每篇必须写到的小节

没有依据的小节可以不写，但要在 `DELIVERY.md` 里说明为什么缺。

1. **它能做什么**：2–3 句。讲清适用场景，也讲清不适用场景。
2. **国内怎么用**：官方支持地区、账号类型、实名、境外手机号、支付方式——只写官方有出处的。接法怎么写都行（接国内 Coding Plan、代理、虚拟卡、代充这些都可以写），但事实要准，别把「听说」写成「官方支持」。
3. **安装**：各形态（桌面 / 命令行 / IDE 插件）分别怎么装。**命令只能抄官方文档**，并标出你核对时的版本和日期。
4. **登录与开通**：怎么登录，要不要先订阅，免费档能用到什么程度。
5. **跑通第一个任务**：一个最小例子，3–5 步，每一步写清「点哪里 / 输入什么 / 看到什么」。
6. **接入自己的模型 / API Key**：能不能填自己的 Key，兼容哪些接口（OpenAI 兼容 / Anthropic 兼容等），以官方文档为准。
7. **怎么付费**：不写死价格，指向站内套餐页或写「价格见本站套餐页」。
8. **常见问题**：3–5 条，每条要有来源（官方 FAQ，或多个来源一致的实际问题）。
9. **延伸阅读**：官方文档 2–4 条；第三方教程 2–3 篇，**只放你实际打开读过正文的**。

### 5.3 写法

- 第二人称，书面但友好。
- 每个操作写清「在哪里点、输入什么、看到什么」，不要写「按照提示操作即可」。
- 坑写成「现象 → 原因 → 怎么办」。
- 每篇正文 **1500–3000 字**（中文字符，不含代码块和表格）。
- 不要 AI 腔：「强大的」「一站式」「赋能」「轻松上手」「无论你是……还是……」「在当今 AI 时代」。
- 每个事实都要能在 frontmatter 的 `sourceUrls` 里找到依据；官方和第三方说法冲突时以官方为准，并把冲突记在 `DELIVERY.md`。

### 5.4 截图

- **每篇至少 6 张**。
- 图片来源放开：你自己实机截的、官方页面上的图、别人教程里的图，都能用。但有三条：
  - **每张图都要在图注里写明来源**——「本人实机截图」/「官方页面：https://…」/「第三方教程：https://…」；
  - **每篇至少留 2 张自己实机截的**，作为你真的装过、跑过的证据；
  - **图一律下载到本地** `public/guides/<slug>/`，不要直接外链（会失效，也可能被防盗链）。
- **不许** AI 生成假界面，也不许拿宣传图冒充「你自己看到的界面」——图注里写清楚它是什么。
- 文件名用 `01-下载页.png`、`02-登录.png` 这种。
- 图里不能出现账号名、邮箱、API Key、真实姓名、本机用户名。官方的和别人的图如果有，一样要打码或裁掉。
- 每张图要有 alt，写清「这张图在证明什么」（例如「官方下载页，红框是 Windows 版入口」）。
- 宽度控制在 1600px 以内，单张 500KB 以内。

### 5.5 真实性

- 必须真的安装、真的登录、真的跑通。跑不通就在教程里写清楚卡在哪、试了什么、为什么没成——**这比编一个顺利的流程得分高**。
- 不许编造菜单项、按钮名、界面截图。
- 界面和你写的不一致时，以你本机为准，并在文末写一句「版本说明」。

## 6. 不做

- 不做搜索、登录、后台、多语言、暗色/亮色切换（皮肤切换器是加分项，不是必须）。
- 不把教程正文硬编码进组件里——必须走导入链路。
